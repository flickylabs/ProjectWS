## 1. 절대 금지 패턴

### 번역체 9패턴

| # | 패턴 | 대안 |
|---|------|------|
| 1 | ~된 것으로 생각됩니다 | ~인 것 같습니다 / ~로 보입니다 |
| 2 | ~인 측면이 있었습니다 | ~인 면이 있었습니다 |
| 3 | 부득이하게 | 어쩔 수 없이 / 할 수 없이 |
| 4 | ~에 대한 부분 | ~에 대해 / ~부분 |
| 5 | 해당 금액 (S3+ 이전) | 그 돈 / 얼마 |
| 6 | 상기 | 위의 / 아까 |
| 7 | 사전 상의/협의 (S0~S2) | S3+ 에서만 허용 |
| 8 | 미리 말씀드리지 못한 | 말씀 못 드린 |
| 9 | 특정 X | 어떤 X / 그 X |

### 기계적 관찰문 (재판관 질문/시스템 메시지)

| 금지 | 대안 |
|------|------|
| "태도에 변화가 감지됩니다" | "진술이 달라지기 시작한다" |
| "내용이 확인됩니다" | "~라는 얘기가 나왔습니다" |
| "흐름이 나타납니다" | "~쪽으로 바뀌고 있습니다" |

### 직접 인용 금지

| 금지 | 대안 |
|------|------|
| `'${prev}'라고 하셨는데, '${curr}'라는 내용이 확인됩니다` | "아까는 ~쪽으로 말씀하셨는데, 지금은 ~. 왜 달라졌습니까?" |

### 기타 금지

| 패턴 | 규칙 |
|------|------|
| "~만을" | "~만" 으로 |
| "상대방" | 실명 사용 |

## 2. 호칭 규칙

| 화자 → 대상 | 규칙 | 예시 |
|-------------|------|------|
| 재판관 → 당사자 | "{이름} 씨" | "박지연 씨" |
| 당사자 → 재판관 | 합니다체 | "~입니다", "~했습니다" |
| 당사자 → 상대에게 직접 | callTerms.toPartner | "자기야", "형" |
| 당사자 → 재판관에게 상대 언급 | callTerms.toJudge | "제 남편이", "제 동생이" |
| 당사자 격앙 시 | callTerms.angry | "이준호!", "윤태성!" |
| 당사자 간 | 반말 유지 | |

### 절대 금지 호칭
- 재판관이 "제 아내/남편" 사용
- NPC가 자기 배우자를 "OOO 씨"로 호칭 (그건 재판관 전용)

## 5. ScriptedText variant 품질 규칙

| 규칙 | 설명 |
|------|------|
| 변형 간 90% 이상 동일 금지 | 같은 키의 5변형이 거의 같은 텍스트면 안 됨 |
| 변형 간 톤 일관성 | 같은 stanceHint 내에서 톤이 갑자기 뒤집히면 안 됨 |
| behaviorHint 구체성 | "화난다" ❌ → "주먹을 쥐며 시선을 내린다" ✓ |
| 200~400자 권장 | 너무 짧으면 빈약, 너무 길면 UI 넘침 |

## 6. 검증 체크리스트

### 자동 검증

```bash
# 빌드
npx tsc -b --force

# 데이터 검증 (A/B 리터럴, 필수 필드, anchorTruth 노출 등)
node tests/stage1-deep-audit.cjs

# 헤드리스 플레이스루
node tests/run-84-headless.cjs --category {category}
```

### 수동 검증

```
□ 모든 dispute name에 A/B 리터럴 없음
□ 모든 evidence name/description에 A/B 리터럴 없음
□ Phase 1 대화에서 anchorTruth 핵심이 노출되지 않음
□ unlockCondition 체인: 동시 해금 불가능 확인
□ DossierCard ID가 dc-N 형식
□ ScriptedText dossier 키가 dc-N.{party}.qN 형식
□ aftermath 5종 모두 존재
□ callTerms가 Phase1/ScriptedText에서 일관 사용
□ 번역체 9패턴 0건
□ 기계적 관찰문 0건
□ 증인 speechStyle이 증언 텍스트에 반영됨
□ correctResponsibility 합계 = 100 (모든 쟁점)
```
