# Session-First Case Generation Guide

Status: controller correction from `PROJECT_CONTROL_TOWER`

## Core Rule

Every case must start from the selected **Session**.

A Session is not a decorative category. The conflict, evidence, witnesses, and final dilemma must be rooted in something that naturally happens inside that Session type.

If a case can be moved to another Session type with only name changes, it is the wrong concept.

## What This Means

### Spouse Session

The core event must be specific to marriage or long-term cohabiting partnership.

Good centers:

- shared household finances
- joint housing decisions
- spouse consent and betrayal
- career sacrifice inside marriage
- domestic labor and invisible work
- family planning
- caregiving responsibilities
- in-law pressure
- private information known only inside the marriage
- joint accounts, joint loans, insurance beneficiaries, lease/mortgage obligations
- separation/divorce preparation, if handled without sensationalism

Weak centers:

- generic repair disputes
- generic neighbor complaints
- generic workplace conflict
- generic privacy leak
- generic money dispute that could happen between roommates

### Family Session

The conflict must depend on blood/adoptive family, inheritance, caregiving, parent-child expectations, sibling hierarchy, elder care, or family history.

### Friend Session

The conflict must depend on friendship trust, shared history, informal promises, social circles, loyalty, emotional debt, or boundaries that are not legally formalized.

### Other Sessions

Use the same principle: the central incident must be native to that Session.

## Decision Test

Before drafting details, answer:

1. Why can this case only or best happen in this Session?
2. What would break if the parties were not in this relationship?
3. Which evidence exists because of this relationship?
4. Which witness has relevant access because of this relationship?
5. What final dilemma is emotionally specific to this relationship?

If these answers are weak, reject the concept.

## Required Human-Readable Brief

Every concept packet must include a controller-readable summary:

- 전체 시놉시스
- 왜 이 Session 사건인지
- A의 표면 입장
- B의 표면 입장
- 실제 숨은 진실
- 진실 단계별 확장
- 쟁점 목록
- 증거 목록
- 증인 목록
- 플레이어가 초반/중반/후반에 무엇을 믿게 되는지
- 기존 사건과 겹치지 않는 점
- 민감도 리스크
- 번역 리스크

Generator-internal notes are not enough for controller review.
