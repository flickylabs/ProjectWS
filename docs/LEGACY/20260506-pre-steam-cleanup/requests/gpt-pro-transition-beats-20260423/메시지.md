# GPT Pro 요청 — transitionBeats 전수 보강 (3사건)

## 배경

Solomon Court 프로젝트 3건 활성 사건(spouse-01/family-01/friend-01)의
`transitionBeats`가 심각하게 부족함. QA 2차에서 WARN으로 드러남.

- **spouse-01**: **0건** (완전 미작성)
- family-01: 9건 (주로 S1-S3 범위, S4/S5 거의 없음)
- friend-01: 9건 (마찬가지)

총 **77개** 전이 비트를 생성해야 함.

## transitionBeat이란

NPC의 lieState가 한 단계 전이될 때(예: S2→S3) 화면에 삽입되는
**3인칭 내레이션**. 당사자 말풍선이 아니라 시스템 내레이션으로 렌더됨
(최근 커밋 `2706e34`에서 확정).

예시 (family-01 기존 beat):
```json
{
  "id": "family-01-beat-b-d1-s1-s2",
  "caseId": "family-01",
  "party": "b",
  "disputeId": "d-1",
  "fromState": "S1",
  "toState": "S2",
  "primaryBeatType": "evidence_hit",
  "line": "윤정후는 어머니가 말년에 늘 헷갈렸던 건 아니라며, 적어도 유서를 읽을 때만큼은 무슨 뜻인지 알고 있었다고 한 발 물러난다.",
  "behaviorHint": "질문이 들어오자 대답 사이 간격이 길어지고 시선이 서류 끝으로 미끄러진다."
}
```

## 스키마

각 beat 객체:
```jsonc
{
  "id": "{caseId}-beat-{party}-{disputeId}-{fromState-lowercase}-{toState-lowercase}",
  "caseId": "spouse-01" | "family-01" | "friend-01",
  "party": "a" | "b",
  "disputeId": "d-1" | "d-2" | ... | "h-d3" | ...,
  "fromState": "S0" | "S1" | "S2" | "S3" | "S4",
  "toState": "S1" | "S2" | "S3" | "S4" | "S5",
  "primaryBeatType": "evidence_hit" | "partial" | "confession" | "emotional" | "counter_shift",
  "line": "3인칭 서술문 — 당사자 이름 + 행동/인정/반응 묘사. 1~2문장, 30~70자.",
  "behaviorHint": "행동 묘사 — 시선/손/말끝 등 구체적 비언어 표지. 1문장."
}
```

### primaryBeatType 선택 가이드
- `evidence_hit`: 증거 제시로 밀린 전이 (S0→S1, S1→S2 주로)
- `partial`: 일부 인정 (S1→S2, S2→S3)
- `counter_shift`: 책임 전가 (S2→S3, S3→S4)
- `emotional`: 감정 호소/분노 (S3→S4)
- `confession`: 자백 (S4→S5, 드물게 S2→S3)

## 품질 규칙 (절대 준수)

1. **3인칭 서술체** — "OOO은/는 …한다" 형식. 당사자 이름을 주어로 시작.
2. **번역체 금지** — "된 것으로 생각됩니다", "측면이 있었습니다" 등 절대 금지
3. **메타 누출 금지** — "플레이어", "재맥락화", "후반에는" 등 내부 용어 금지
4. **호칭 규칙** — 당사자 실명 사용 (박지연/이준호/윤태성/윤정후/송다은/최수민)
5. **쟁점 실체 누출 금지** — hidden dispute(h-d*)의 경우 직접적 진실 노출 대신 "흔들린다/굳어진다" 식 간접 표현
6. **다양성** — 같은 beatType 내에서 동사/구조 반복 피하기
7. **tone 매칭** — archetype 반영 (spouse-01 A=avoidant, B=cold_logic / family-01 A=confrontational, B=affect_flattening / friend-01 A=confrontational, B=avoidant)

자세한 규칙: `refs/quality-rules.md`

## 스토리 배경 요약 (beat 작성에 필수)

### spouse-01 (박지연 vs 이준호)
- A(박지연): 남편이 딴살림을 차렸다고 확신 → 위임장 조작으로 공동 적금 **3,000만원** 해지 → 투자방 사기로 전액 손실
- B(이준호): 외도 아님. 개인회생 중인 **친형의 조카(중2) 돌보던 중**, 개인 비자금 **2,000만원**을 형에게 전달

### family-01 (윤태성 vs 윤정후)
- A(윤태성): 어머니 유서가 60:40으로 자기에게 불리하게 조작됐다고 주장
- B(윤정후): 원래 90:10이던 유서를 60:40으로 고쳐 씀 — **자기 몫을 줄인** 조작. 이유: 형의 출생 비밀(일기장으로 안 사실)을 지키려는 배려

### friend-01 (송다은 vs 최수민)
- A(송다은): 친구가 예비신랑에게 9일간 연락하며 집착했다고 단톡방에 매도
- B(최수민): 송다은 아버지의 사기 패턴을 알아채고 예비신랑에게 **경고** 시도. 과거 본인도 피해자였음

## 주의

- spouse-01 h-d3, h-d4는 **hidden 쟁점** — 초반 단계(S0/S1)에서는 "그 일", "그 숫자" 같은 간접 표현만. S3+에서 실명·금액 허용
- "진실은 플레이어가 직접 밝혀낸다" — 비트가 사건 전모를 먼저 요약하지 말 것
- behaviorHint는 `🎭 {behaviorHint}` 형태로 시스템 메시지에 별도 렌더됨. 비언어 표지(시선/손/숨/말끝) 위주, 감정 이름만 적으면 안 됨
