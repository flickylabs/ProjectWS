## (A) ProcessMetrics 미추적 보너스 3종 연결

### 문제
`src/engine/verdictEngine.ts`에서 `(pm as any).combinationDossierUnlocked`, `counterQuestionUsed`, `bothSidesS3Plus`를 참조하지만 ProcessMetrics 타입에 해당 필드가 없고, 어디서도 집계하지 않아 보너스(+10, +5, +10)가 영구적으로 0입니다.

### 수정 내용

1. `src/types/index.ts` (또는 ProcessMetrics가 정의된 파일)에 3필드 추가:
```ts
combinationDossierUnlocked: number  // 조합 DossierCard 해금 횟수
counterQuestionUsed: number         // 반격 질문 사용 횟수
bothSidesS3Plus: boolean            // 양쪽 NPC 모두 S3 이상 도달 여부
```

2. `src/hooks/useActionDispatch.ts`에서 해당 이벤트 발생 시 `trackMetric()` 호출:
- `combinationDossierUnlocked`: DossierCard 해금 시점 (dossier 관련 로직에서 `v4:dossier-unlock` 이벤트 디스패치 근처)
- `counterQuestionUsed`: 반격 질문(counter_question) 사용 시점
- `bothSidesS3Plus`: 매 턴 종료 시 양쪽 lieState 체크 → 둘 다 S3 이상이면 true로 set

3. `src/engine/verdictEngine.ts`에서 `(pm as any)` 캐스팅을 정식 타입 접근으로 교체

### 확인 방법
- `npx tsc -b --force` 통과
- verdictEngine의 해당 보너스 분기에서 undefined가 아닌 실제 값 사용 확인

## (B) 증인 소환 LLM 실패 시 토큰 환불

### 문제
`generateWitnessTestimony` LLM 호출이 실패하면 토스트만 표시되고 소비된 토큰(investigationTokens 1개)이 환불되지 않습니다.

### 수정 내용

`src/hooks/useActionDispatch.ts`에서 `generateWitnessTestimony` 호출부의 catch 블록:
```ts
// 기존: 에러 토스트만
// 수정: 토큰 환불 + 메시지 변경
catch (error) {
  state.gain('investigationTokens', 1)  // 환불
  // 토스트: "증인 증언 생성에 실패했습니다. 토큰이 반환되었습니다."
}
```

### 확인 방법
- `npx tsc -b --force` 통과
- catch 블록에 gain 호출이 있는지 코드 확인
