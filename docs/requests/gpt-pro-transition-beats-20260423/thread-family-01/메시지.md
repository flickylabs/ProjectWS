## 1. transitionBeat 이란

Solomon Court는 재판 시뮬레이션 추리 게임입니다. NPC는 거짓말 상태 기계(LieState S0→S5)를 따르며, 질문·증거·추궁에 의해 한 단계씩 전이합니다.

- S0: 완전 부정 → S1: 일부 인정 → S2: 핑계 → S3: 책임 전가 → S4: 감정적 → S5: 자백

`transitionBeat`는 한 전이가 일어난 직후 화면에 삽입되는 **3인칭 내레이션**입니다. 당사자 말풍선이 아니라 시스템 내레이션(system speaker)으로 렌더됩니다.

### 기존 family-01 beat 예시 (톤 기준선)

```json
{
  "id": "family-01-beat-b-d1-s1-s2",
  "caseId": "family-01",
  "party": "b",
  "disputeId": "d-1",
  "fromState": "S1",
  "toState": "S2",
  "primaryBeatType": "evidence_hit",
  "line": "윤정후는 어머니가 말년에 늘 헷갈렸던 건 아니라며, 적어도 유서를 읽을 때만큼은 무슨 뜻인지 알고 있었다고 한 발 물러난다.",
  "behaviorHint": "질문이 들어오자 대답 사이 간격이 길어지고 시선이 서류 끝으로 미끄러진다."
}
```

**첨부된 `family-01-game-events.json`의 `transitionBeats` 배열(line 100~200 부근)에 기존 9건이 들어 있습니다. 이 9건의 톤과 길이, 문장 리듬을 참고해서 새 29건을 작성해주세요.**

## 2. 스키마

각 beat 객체:

```jsonc
{
  "id": "family-01-beat-{party}-{disputeId}-{fromState-lowercase}-{toState-lowercase}",
  "caseId": "family-01",
  "party": "a" | "b",
  "disputeId": "d-1" | "d-2" | "d-3" | "d-4" | "d-5",
  "fromState": "S0" | "S1" | "S2" | "S3" | "S4",
  "toState": "S1" | "S2" | "S3" | "S4" | "S5",
  "primaryBeatType": "evidence_hit" | "partial" | "confession" | "emotional" | "counter_shift",
  "line": "3인칭 서술문. 당사자 이름을 주어로 시작. 1~2문장, 30~70자.",
  "behaviorHint": "비언어 표지(시선/손/숨/말끝) 묘사. 1문장."
}
```

### primaryBeatType 선택 가이드

| Type | 용도 | 주 전이 |
|------|------|---------|
| `evidence_hit` | 증거 제시로 밀린 전이 | S0→S1, S1→S2 |
| `partial` | 일부 인정 | S1→S2, S2→S3 |
| `counter_shift` | 책임 전가 | S2→S3, S3→S4 |
| `emotional` | 감정 호소/분노 | S3→S4 |
| `confession` | 자백 | S4→S5 (드물게 S2→S3) |

### id 포맷 주의

disputeId의 하이픈은 **그대로** id에 포함:
- `disputeId: "d-1"` + `fromState: "S0"` + `toState: "S1"` → `id: "family-01-beat-a-d-1-s0-s1"`

## 3. 품질 규칙 (절대 준수 — 자세히는 소스의 `quality-rules.md`)

### 3.1 절대 금지

- **번역체 9패턴**: "~된 것으로 생각됩니다", "~인 측면이 있었습니다", "부득이하게", "~에 대한 부분", "해당 금액(S3+ 이전)", "상기", "사전 상의/협의(S0~S2)", "미리 말씀드리지 못한", "특정 X"
- **메타 누출**: "플레이어", "재맥락화", "후반에는", "단계", "lieState" 같은 내부 용어 절대 금지
- **1인칭/2인칭**: "나는", "당신은" 금지. 3인칭 서술체.
- **"~만을"** → "~만" 으로
- **"상대방"** → "상대측" 또는 실명

### 3.2 3인칭 서술체

- 당사자 실명(윤태성/윤정후)을 주어로 시작 권장
- "윤태성은 ~한다", "윤정후가 ~한다" 패턴
- 대명사("그는/그녀는") 과다 사용 지양 — 실명이 자연스러움

### 3.3 Truth Throttle

lieState별 공개 가능한 정보 수준:

| State | 금액/비율 | 인물 |
|-------|----------|------|
| S0-S1 | "그 비율" / "그 숫자" | "어머니" / "그 사람" |
| S2 | 간접 서술 | 약칭 |
| S3+ | 구체적(90:10 / 60:40) | 실명 |
| S4 | 실수로 노출 허용 | 실수로 노출 허용 |
| S5 | 전부 공개 | 전부 공개 |

**beat에도 이 규칙이 적용됩니다.** S0/S1 단계 beat에서 "60:40", "90:10", "출생 비밀", "일기장" 등 구체 정보 직접 노출 금지. 간접 표현 사용.

### 3.4 핵심 숨김 쟁점 특별 규칙

family-01의 **진짜 진실**은: B(윤정후)가 원래 **90:10**이던 유서를 **60:40**으로 고쳐 써서 **자기 몫을 줄이는** 방향으로 조작했다는 것. 이유는 형(윤태성)의 **출생 비밀**(일기장으로 안 사실)을 지키려는 배려.

- S0/S1/S2 beat에서는 이 "자기 몫 축소" 방향성 직접 서술 **절대 금지**.
- S3+부터 "숫자가 내 쪽이 적게 나왔다는 점에 대해" 식으로 점진 접근.
- S4~S5 beat에서만 "출생 비밀" / "일기장" 같은 핵심 단서 등장 허용.

### 3.5 behaviorHint 구체성

- ❌ "화난다", "놀란다", "슬프다" (감정 이름만)
- ✅ "주먹을 쥐며 시선을 내린다", "눈을 크게 뜨고 입이 살짝 벌어진다", "목이 메이며 말끝이 떨린다"
- 신체 표현 최소 1개 필수 (시선, 자세, 손, 표정, 목소리)

### 3.6 다양성

- 같은 beatType·같은 당사자 내에서 동사/구조 반복 피하기
- 29건 전체에서 `~한다`로 끝나는 동사 3~4종 이상 섞기

### 3.7 톤 균형

- 기존 9건과 신규 29건의 **문장 리듬이 튀지 않도록** 맞추기 — 기존 예시를 먼저 숙지한 뒤 작성 권장

## 4. family-01 스토리 배경 (필수 숙지)

- **A = 윤태성** (형): 어머니 유서가 60:40으로 자기에게 불리하게 조작됐다고 주장. 실제로는 자기가 **더 많이 받는 쪽**이었는데 원본을 몰라서 오해.
- **B = 윤정후** (동생): 원래 **90:10**(자기 90, 형 10)이던 유서를 **60:40**(자기 60, 형 40)으로 고쳐 씀. 자기 몫을 줄이는 조작. 이유는 형의 출생 비밀(둘은 사실 **어머니 혼자 낳은 이복 형제 관계** — 구체 진실은 게임 내에서 드러남)을 지키려는 배려.

### 쟁점 5종 (family-01 기존 game-events.json에 정의됨)

`d-1 ~ d-5` — 어머니 말년 인지능력, 유서 작성 경위, 필적/서명, 원본 소재, 윤정후의 단독 수정 등 쟁점이 순차 추궁됩니다.

### 캐릭터 archetype

- **A(윤태성) = confrontational (공격적)**: 직설적 추궁, 분노 표출, 단호함. 격앙 시 목소리 커짐.
- **B(윤정후) = affect_flattening (감정 평탄화)**: 감정을 억누른 담담함. 표정 변화 적음. 무너질 때도 조용히 무너짐.

이 archetype은 line/behaviorHint 표현에 반영되어야 합니다.
