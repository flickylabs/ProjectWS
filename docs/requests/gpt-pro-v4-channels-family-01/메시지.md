## 사건 개요

**family-01: 치매 어머니의 유서**

| 역할 | 이름 | 나이 | 직업 | archetype |
|------|------|------|------|-----------|
| A (원고) | 윤태성 | 48 | 주방가구 공장 대표 | confrontational |
| B (피고) | 윤정후 | 44 | 자동차부품 가게 운영 | affect_flattening |

**호칭**:
- A→B 직접: "정후야" / 격앙: "윤정후!"
- B→A 직접: "형" / 격앙: "윤태성!"
- A가 재판관에게 B 언급: "제 동생"
- B가 재판관에게 A 언급: "제 형"

**캐릭터 화법**:
- A(윤태성): 목소리를 높여 상대를 누르고 형이라는 위치를 먼저 내세운다. 불리해지면 동생의 인격을 깎아내리며 질문 자체를 무력화하려 든다.
- B(윤정후): 감정을 최대한 억누르며 사실만 짧게 말한다. 담담해 보이지만 그 담담함이 오히려 의심을 산다. 진짜 감정은 마지막까지 드러내지 않으려 한다.

## 생성할 채널 4종

### 1. contradiction_pursuit (모순 추궁)
모순이 감지된 후 해당 당사자가 방어하는 대사.

**키 형식**: `"party|disputeId|lieState"` (예: `"a|d-1|S1"`)
**구조**: party별, dispute별, lieState별 엔트리. 각 엔트리에 variant 2개.

**커버리지** (핵심만):
- a|d-1|S1, a|d-1|S2, a|d-2|S1, a|d-2|S2
- b|d-1|S1, b|d-1|S2, b|d-2|S1, b|d-2|S2
= 8 엔트리 × 2 variant = 16개

**few-shot 예시** (spouse-01):
```json
{
  "key": "a|d-1|S1",
  "variants": [
    {
      "id": "contra-a-d-1-S1-v1",
      "text": "그건 말이 바뀐 게 아닙니다. 정황을 말씀드린 거지, 없는 일을 지어낸 건 아닙니다.",
      "behaviorHint": "턱을 굳게 세운 채 말끝을 밀어 올린다. 단정이 흔들리는 걸 들키지 않으려 더 세게 버틴다.",
      "tags": ["channel:contradiction_pursuit", "speaker:a", "listener:judge", "stance:deny", "continuity:contradiction_press", "lieState:S1", "disputeId:d-1"]
    },
    {
      "id": "contra-a-d-1-S1-v2",
      "text": "제가 본 걸 그대로 말씀드린 겁니다. 다르게 들리셨다면 그만큼 상황이 이상했다는 뜻입니다.",
      "behaviorHint": "턱을 굳게 세운 채 말끝을 밀어 올린다.",
      "tags": ["channel:contradiction_pursuit", "speaker:a", "listener:judge", "stance:deny", "continuity:contradiction_press", "lieState:S1", "disputeId:d-1"]
    }
  ]
}
```

**작성 규칙**:
- S1: 아직 부인 단계. "말이 바뀐 게 아니라 맥락이 다르다"식 방어.
- S2: 부분 인정. "그 부분은 인정하지만 핵심은 다르다"식 전환.
- 각 당사자의 archetype 화법 반영 (태성=공격적, 정후=담담하게 사실만)
- 재판관 대상 합니다체 필수
- 번역체 금지 (CLAUDE.md 한국어 품질 규칙 참조)

### 2. interjection (끼어들기)
상대 심문 중 참다못해 끼어드는 대사.

**키 형식**: `"party|disputeId|severity"` (minor/major)
**구조**: party별, dispute별, severity별. 각 variant 2개.

**커버리지**:
- a|d-1|minor, a|d-1|major, a|d-2|minor, a|d-2|major
- b|d-1|minor, b|d-1|major, b|d-2|minor, b|d-2|major
= 8 엔트리 × 2 variant = 16개

**few-shot 예시** (spouse-01):
```json
{
  "key": "a|d-1|minor",
  "variants": [
    {
      "id": "interject-a-d-1-minor-v1",
      "text": "잠깐만요, 재판관님. 제 남편이 지금 마치 제가 괜히 단정한 것처럼 말씀하시는데, 그때 보인 정황이 하나가 아니었습니다.",
      "behaviorHint": "참다가도 더는 넘길 수 없다는 듯 낮게 끊어 들어온다.",
      "tags": ["channel:interjection", "speaker:a", "listener:judge", "severity:minor", "stance:blame", "continuity:interruption_minor", "disputeId:d-1"]
    }
  ]
}
```
```json
{
  "key": "a|d-1|major",
  "variants": [
    {
      "id": "interject-a-d-1-major-v1",
      "text": "아니요, 그건 제가 들을 말이 아닙니다! 그렇게 다 숨겨놓고 이제 와서 제가 예민했다고만 하면 끝입니까!",
      "behaviorHint": "감정이 한꺼번에 터져 말이 빨라진다. 억울함과 분노가 섞여 상대를 바로 겨눈다.",
      "tags": ["channel:interjection", "speaker:a", "listener:judge", "severity:major", "stance:blame", "continuity:interruption_major", "disputeId:d-1"]
    }
  ]
}
```

**작성 규칙**:
- minor: 참다가 한마디. 합니다체 유지.
- major: 감정 폭발. 반말 전환 가능.
- A(태성)는 "형인데" 포지션, B(정후)는 "억울하지만 담담하게"
- 호칭: 재판관에게 상대 언급 시 callTerms.toJudge 사용

### 3. emotional_overload (감정 폭발)
감정 포화로 일시 중단 후 회복하는 대사.

**키 형식**: `"party|disputeId"`
**구조**: party별, dispute별. 각 variant 2개. "(두 턴 후)" 회복 포함.

**커버리지**:
- a|d-1, a|d-2
- b|d-1, b|d-2
= 4 엔트리 × 2 variant = 8개

**few-shot 예시** (spouse-01):
```json
{
  "key": "a|d-1",
  "variants": [
    {
      "id": "overload-a-d-1-v1",
      "text": "…더는 말씀 못 드리겠습니다. 지금은 제가 뭘 믿었는지, 왜 그렇게까지 흔들렸는지 같이 올라옵니다. (두 턴 후) …죄송합니다. 다시 말씀드리겠습니다.",
      "behaviorHint": "목이 잠기고 눈물이 먼저 차오른다.",
      "tags": ["channel:emotional_overload", "speaker:a", "disputeId:d-1", "cooldown:2turns", "state:overload"]
    }
  ]
}
```

**작성 규칙**:
- 전반부: 감정 포화 → 말을 잇지 못함
- "(두 턴 후)" 후: 수습하며 다시 진술 의지 표현
- A(태성): 분노/억울함 → 형으로서 체면 무너짐
- B(정후): 오랫동안 억눌렀던 감정이 한꺼번에 → 담담함 균열

---

### 4. evidence_discovery (증거 발견 반응)
증거 조사 시 재판관 질문 → 당사자 실수 노출 시퀀스.

**키 형식**: `"party|evidenceId|step"` (probe/slip/capture/confirm)
**구조**: 4단계 시퀀스. probe/capture는 speaker:judge, slip/confirm은 speaker:party.

**커버리지** (핵심 증거만):
- b|e-1|probe/slip/capture/confirm (유서 사본 — B가 관련)
- b|e-5|probe/slip/capture/confirm (유서 원본 — B가 관련)
- a|e-6|probe/slip/capture/confirm (송금 내역 — A가 반응)
= 3세트 × 4단계 × 1 variant = 12개

**few-shot 예시** (spouse-01):
```json
// probe (재판관 질문)
{
  "key": "b|e-1|probe",
  "variants": [{
    "id": "discover-b-e-1-probe-v1",
    "text": "그날 지출 목록을 보면 생활용품 말고도 다른 물건이 보입니다. 그 부분까지 함께 설명해 주시겠습니까.",
    "behaviorHint": "재판관이 영수증의 겉항목을 훑은 뒤, 사소해 보이는 품목 하나를 조용히 다시 집어 든다.",
    "tags": ["channel:evidence_discovery_sequence", "speaker:judge", "step:probe", "evidenceId:e-1"]
  }]
}
// slip (당사자 실수)
{
  "key": "b|e-1|slip",
  "variants": [{
    "id": "discover-b-e-1-slip-v1",
    "text": "아, 그날은 참고서도… 아닙니다. 그건 지금 말씀드릴 얘기가 아닙니다.",
    "behaviorHint": "무심코 튀어나온 단어를 급히 거둬들인다.",
    "tags": ["channel:evidence_discovery_sequence", "speaker:b", "step:slip", "stance:hedge", "evidenceId:e-1"]
  }]
}
```

**작성 규칙**:
- probe: 재판관이 증거를 기반으로 자연스럽게 질문. 합니다체.
- slip: 당사자가 방심하여 정보를 흘림. "아…" "그건…" 식 실수.
- capture: 재판관이 slip을 포착하여 추궁. "지금 ~라고 하셨는데?"
- confirm: 당사자가 마지못해 일부 인정. 완전 자백 아님.
- 재판관 대사: 기계적 관찰문 금지, 간접 인용, 자연어 질문 (CLAUDE.md 참조)

## 출력 형식

JSON 배열로, 각 채널을 최상위 객체로:
```json
{
  "contradiction_pursuit": { "entries": [ ... ] },
  "interjection": { "entries": [ ... ] },
  "emotional_overload": { "entries": [ ... ] },
  "evidence_discovery": { "entries": [ ... ] }
}
```

각 entry 구조는 few-shot 예시와 동일하게 유지해주세요.

## 절대 규칙
- 번역체 금지: "~된 것으로 생각됩니다", "~인 측면이 있었습니다" 등
- 호칭: 재판관 대상 합니다체, 당사자 간 반말 (호칭은 callTerms 따름)
- "사전 상의/협의" (S0-S2에서 금지)
- "특정 X" 패턴 금지
- 재판관 질문: 기계적 관찰문 금지, 긴 발언 직접 인용 금지
