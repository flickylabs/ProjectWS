# GPT Pro 요청 — spouse-01 v2-atoms 신규 생성

## 이 스레드의 역할

**spouse-01** 사건의 `v2-atoms` 파일(`claimPolicies` 구조)을 신규 생성합니다.
(다른 사건 family-01 / friend-01은 별도 스레드 병렬 진행 중이니 이 스레드에서는 spouse-01만 다뤄주세요.)

현재 활성 3건에는 v2-atoms가 없어서 legacy atom 합성으로 대응 중이고, 그로 인해 NPC 응답 다양성이 부족합니다. 이 스레드로 **spouse-01 고유 claimAtoms 완전 신규 제작**.

---

## 1. 배경 — Solomon Court 게임과 v2-atoms의 역할

Solomon Court는 재판 시뮬레이션 추리 게임. NPC는 거짓말 상태 기계(LieState S0→S5)를 따르며, 각 state에서 공개 가능한 정보 수준이 다름:

- S0: 완전 부정 → S1: 일부 인정 → S2: 핑계 → S3: 책임 전가 → S4: 감정적 → S5: 자백

각 state에서 NPC가 답변할 때 사용하는 **발화 재료**가 `claimAtoms`. 완성 대사가 아니라 **의미 원자**.

런타임 흐름:
1. 플레이어 질문(subAction: fact_pursuit/motive_search/empathy_approach/evidence_present) 접수
2. `atomSelectionEngine`이 현 state의 claimAtoms 중 subAction 규칙에 맞는 것 2개 선택
3. `blueprintPromptBuilderV2`가 atom들의 `factText + slots`를 조합해 LLM 프롬프트 구성
4. 또는 scriptedText 스크립트가 우선 (LLM은 폴백)

당신이 만들 claimAtoms는 **이 조합의 재료 풀**. 다양성·정확성·일관성이 중요.

## 2. 스키마 (필수 — 공통 소스 `claim-atom-schema.md` 정독 선행)

### 파일 최상위
```jsonc
{
  "caseId": "spouse-01",
  "schemaVersion": "v2",
  "claimPolicies": {
    "a": { "d-1": { S0..S5 }, "d-2": {...}, "h-d3": {...}, "h-d4": {...} },
    "b": { "d-1": {...}, "d-2": {...}, "h-d3": {...}, "h-d4": {...} }
  }
}
```

### 각 `claimPolicies.{party}.{disputeId}.{state}` 블록
```jsonc
{
  "disputeId": "d-1",
  "state": "S0",
  "schemaVersion": "v2",
  "claimAtoms": [ClaimAtom, ...],    // 3~5개 권장
  "privateKnowledge": [...],          // NPC 내면 진실 (2~4개 서술문)
  "suppressions": [...],              // 절대 안 꺼내는 것 (2~4개)
  "emotionalLeakRisk": "none" | "low" | "mid" | "high",
  "tellPool": [...]                   // verbal tell (archetype 기반)
}
```

### ClaimAtom
```jsonc
{
  "id": "d1.meaningKey",              // 쟁점단축명.의미키 (snake_case)
  "factText": "의미 라벨 10~30자",    // 완성 문장 ❌, 의미 요약 ✅
  "tags": ["act", "timeline"],        // ClaimAtomTag 중 2~4개
  "slots": {                          // 가능한 모든 mode 채움 (런타임이 선택)
    "amount": { "exact": "...", "rounded": "...", "neutral": "..." },
    ...
  },
  "stanceHints": ["deny", "hedge"],   // Stance 1~3개
  "source": "v2"
}
```

**중요**: `factText`는 완성 대사 아님. "나는 그날 돈을 옮겼어요"는 ❌. "공동계좌 금액 이동 사실만 인정"은 ✅.

## 3. spouse-01 스토리 배경 (필수 숙지)

### 중심 사건 — 부부 5,000만원 증발
- A = **박지연** (36, 학원 데스크)
- B = **이준호** (38, 가전매장)

### 숨은 진실 (플레이어가 직접 밝혀내야 함)
1. B(이준호)의 오피스텔 방문·새벽 전화 = **외도 아님**. 친형(개인회생 중) 집에서 **중2 여조카** 돌봄(밥/생필품). 형은 빚 갚으려 야간 일.
2. B는 개인 비자금 **2,000만원**을 형에게 건네 빚 갚음. 아내에게 숨김.
3. 이유: **시댁 얘기 꺼내면 가정 폭발**(박지연과 시댁 불화 극심).
4. A(박지연)는 외도 확신 → **공동 적금 3,000만원을 위임장 조작으로 해지** → 이혼 대비 개인 확보 → 투자방 사기에 전액 손실.
5. 은폐 순서: **B 먼저 숨김, A가 선제적으로 적금 해지**.

### 4대 쟁점

#### d-1 (공개): 오피스텔 방문과 새벽 전화
- 겉으로는 외도 의심
- 진실: 조카 돌봄
- A의 주장: "매일 같은 오피스텔 2시간, 새벽 통화 = 외도"
- B의 주장: "오해. 사정 있다"
- 주 responder: B (이준호)

#### d-2 (공개): 개인 비자금 2,000만원 출금
- 계좌 기록 증거 확실
- 진실: 형에게 전달
- A의 주장: "여자한테 쓴 돈"
- B의 주장: "가족 일"
- 주 responder: B

#### h-d3 (숨김): 공동 적금 3,000만원 해지 위임장 조작
- 증거는 은행 서류 조작 흔적
- 진실: 박지연이 위임장 조작으로 단독 해지 → 투자방 사기
- A는 초반 "모른다" → 후반 자백
- 주 responder: A (박지연)

#### h-d4 (숨김): 은폐와 선제행동의 순서
- 누가 먼저 숨겼고 누가 선제공격했나
- 진실: B 먼저 숨김 → A가 선제 해지
- 양측 공방 쟁점
- 주 responder: A, B 둘 다

### 캐릭터 archetype (인용 의존 없이 맥락만 반영)
- **A (박지연) = avoidant / victim_cosplay**: 회피하다가 압박 시 감정 폭발. 피해자 프레임 애용.
- **B (이준호) = cold_logic / avoidant**: 차분하고 논리적으로 답변. 깊숙한 가족 진실은 끝까지 회피.

## 4. 쟁점별 + 파티별 atom 설계 지침

각 lieConfig(party × dispute × state)마다 **3~5개 atom**.

### 다양성 요구 (다음 관점 골고루 포함)
각 (party, disputeId, state) 블록의 claimAtoms는 최소 아래 4개 관점 중 3개 이상 포함:
1. **act / timeline** 계열 — fact_pursuit 대응 ("무엇을 했는지")
2. **motive / self_justification** 계열 — motive_search 대응 ("왜 그랬는지")
3. **emotion / shame / fear / relationship** 계열 — empathy_approach 대응 ("심정")
4. **evidence / context / quote / identity** 계열 — evidence_present 대응 ("증거 맥락")

### state별 atom 성격 변화 예시

**B (이준호) / d-1 (오피스텔) 진화 예시**:

| state | atom 구성 방향 |
|-------|---------------|
| S0 | 방문 자체만 인정 / 통화 부인 / 회피 tell |
| S1 | 통화 인정하되 집안일 돌림 / 방문 빈도 일부 인정 |
| S2 | 가족 문제 때문이라고 둘러댐 / 시댁 얘기 꺼리는 눈치 |
| S3 | 형 집이라고 범위 좁힘 / 아내 의심이 이유라고 책임 전가 |
| S4 | 조카 돌본 일을 외도로 몰아간 억울함 감정 폭발 |
| S5 | 형 집에 조카 돌봄, 새벽 전화는 조카 문제 완전 자백 |

**A (박지연) / h-d3 (적금 해지) 진화 예시**:

| state | atom 구성 방향 |
|-------|---------------|
| S0 | "그 서류"에 대해 자신과 무관 주장 |
| S1 | 돈 흐름을 모르지는 않는다며 이준호를 의심한 이유 앞세움 |
| S2 | 급한 사정이었다며 구체 설명 유예 |
| S3 | 공동 적금 해지 서류에 손댄 사실 인정, 이준호의 은폐 탓 |
| S4 | 외도 의심이 자신을 몰았다며 무너짐 |
| S5 | 위임장으로 3,000만원 해지하여 투자방에 보냈다 잃은 전말 자백 |

### Hidden 쟁점 (h-d3, h-d4) 특별 규칙

- **S0/S1에서 실체 정보 절대 노출 금지**
  - 금액: "그 돈", "얼마" (neutral만)
  - 위임장 / 투자방 / 사기 같은 구체 단어: S3+에서만
  - "그 서류", "그 일", "그날 판단" 수준
- **S3부터 점진 공개**. S4에서 감정과 함께 터짐. S5에서 전면 자백.

### Truth Throttle 슬롯 매핑

각 atom의 slot에 가능한 모든 mode 채움:

| State 범위 | amount | time | person |
|-----------|--------|------|--------|
| S0-S1 | neutral | neutral | neutral/judgeRef |
| S2 | rounded | period | judgeRef |
| S3+ | exact | dateExact | fullName |
| S4 | 실수 노출 허용 | ... | ... |
| S5 | 전부 | 전부 | 전부 |

→ 당신은 **가능한 모든 mode를 atom.slots에 채워둠**. 런타임이 state에 따라 선택.

## 5. id 명명 규칙 + 재사용

- 형식: `{disputeIdShort}.{meaningKey}`
  - disputeIdShort: `d-1` → `d1`, `h-d3` → `hd3`, `h-d4` → `hd4`
  - meaningKey: 의미 축약 (snake_case). 예: `movement_only`, `motive_shame`, `partial_admission`
- 같은 atom이 S0~S5에 등장 OK. slot 값만 state별로 승격시킴.
- 다른 party 간 같은 id 금지 (서로 다른 관점).

예:
- `d1.visit_only` — B의 d-1 S0에 "방문 사실만 인정"
- `d1.phone_family` — B의 d-1 S2에 "통화는 집안일이라 둘러댐"
- `hd3.money_unknown` — A의 h-d3 S0에 "그 돈 흐름 모른다"
- `hd3.partial_forgery` — A의 h-d3 S3에 "해지 서류 손댔다 인정"

## 6. 한국어 품질 규칙 (절대 준수 — 공용 소스 `quality-rules.md`)

### factText
- 의미 라벨. 10~30자 서술 축약.
- 번역체 금지 ("~된 것으로 생각됩니다" 등 9패턴).
- 완성 대사 금지.

### slots 내 value
- **이름**: A/B 리터럴 금지. **박지연 / 이준호** 실명.
- **호칭**: `judgeRef`는 "제 남편" / "제 아내" 식 (재판관에게 지칭). `directRef`는 "자기" 같은 부부 호칭. `angryRef`는 감정 폭발 시 "이준호 씨!" 같은 격앙 호칭.
- **금액**: S0-S2 neutral "해당 금액" / "그 돈". S3+ exact "3,000만원" / "2,000만원".
- **시간·장소·증거**: Truth Throttle 엄수.

### privateKnowledge / suppressions
- 서술문 OK. 1~2문장.
- 메타 누출 금지 ("플레이어", "lieState" 등).

### tellPool (verbal tell — archetype별)
- **A (avoidant/victim_cosplay)**: `topic_shift`, `victim_frame`, `vague_generalization`, `tear_up`, `blame_deflection`, `uncertain_hedge`
- **B (cold_logic/avoidant)**: `answer_delay`, `fact_reframe`, `answer_only`, `partial_admission`, `timeline_correction`, `calculation_appeal`

**이번 사건 structure-v2.json에 정의된 `verbalTells`를 우선 사용**. 첨부된 `spouse-01-structure-v2.json` 확인.
