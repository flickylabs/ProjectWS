# GPT Pro 요청 — friend-01 v2-atoms 신규 생성

## 이 스레드의 역할

**friend-01** 사건의 `v2-atoms` 파일(`claimPolicies` 구조)을 신규 생성합니다.
(다른 사건 spouse-01 / family-01은 별도 스레드 병렬 진행 중이니 이 스레드에서는 friend-01만 다뤄주세요.)

현재 활성 3건에는 v2-atoms가 없어 legacy atom 합성으로 대응 중이고, NPC 응답 다양성 부족이 발생. 이 스레드에서 **friend-01 고유 claimAtoms 완전 신규 제작**.

---

## 1. 배경 — Solomon Court와 v2-atoms

Solomon Court는 재판 시뮬레이션 추리 게임. NPC는 거짓말 상태 기계(LieState S0→S5)를 따름:

- S0: 완전 부정 → S1: 일부 인정 → S2: 핑계 → S3: 책임 전가 → S4: 감정적 → S5: 자백

각 state에서 NPC가 답변할 때 사용하는 **발화 재료**가 `claimAtoms`. 완성 대사가 아니라 **의미 원자**.

런타임 흐름:
1. 플레이어 질문(subAction: fact_pursuit / motive_search / empathy_approach / evidence_present) 접수
2. `atomSelectionEngine`이 현 state의 claimAtoms 중 subAction 규칙에 맞는 것 선택
3. `blueprintPromptBuilderV2`가 `factText + slots` 조합해 LLM 프롬프트 구성

당신이 만들 claimAtoms는 이 조합의 **재료 풀**.

## 3. friend-01 스토리 배경 (필수 숙지)

### 중심 사건 — 손절한 절친
- A = **송다은** (31, 온라인 쇼핑몰 CS)
- B = **최수민** (31, 필라테스 강사)

### 숨은 진실 (플레이어가 직접 밝혀내야 함)
1. A가 단톡방에서 "B가 내 예비신랑에게 접근하며 집착한다" 매도 → B는 차단으로 해명 불가 → 고립.
2. 사실: **예비신랑이 B에게 먼저 찝적댐** (술자리 후 연락, 둘이 만나자 등). B는 "A 남자친구잖아" 선 긋음.
3. B가 예비신랑에게 연락한 **진짜 이유**: A **아버지**가 예비신랑에게 **사기 시도 정황** 포착. 물증 없음. A에게 말할 방법 없음 (손절 + 공통 친구 있음).
4. **과거 손절 사건의 전말**: 과거에 A 아버지가 B에게 **사기** 침. B는 "네 아빠가 사기꾼"이라 차마 못 말함. A는 "B가 돈 때문에 변했다" 오해 → 손절.
5. A 아버지가 과거 B에게 한 수법을 이번엔 예비신랑에게. B가 알아본 것. "또 당하게 둘 수 없다." 근데 또 말 못하고 또 B만 악역.

### 5대 쟁점 (첨부 `friend-01-structure-v2.json` 참조)

#### d-1 (공개): 9일간의 연락 의도
- A: "집착 / 접근"
- B: "경고 시도" (진실), 초반엔 회피
- 주 responder: 양측

#### d-2 (공개): 예비신랑의 선넘는 접근
- 진실: 예비신랑이 B에게 먼저 접근
- A: "B가 꼬셨다"
- B: 사실 밝히려다가 A 상처 우려 주저
- 주 responder: 양측

#### d-3 (숨김): 아버지의 돈 접근 패턴
- 진실: A 아버지가 예비신랑에게 투자 명목 접근 = 과거 B에게 썼던 수법
- A: "내 아버지를 끌어들이지 말라" 분노
- B: S5에서 완전 공개
- 주 responder: B 중심

#### d-4 (숨김): 과거 손절과 아버지의 사기
- 진실: 과거 A 아버지가 B에게 사기. B는 돈 잃고 친구 관계도 잃음.
- A: "B가 돈 때문에 변했다" 오해
- B: S5에서 "피해자였고 조용히 사라진 것" 자백
- 주 responder: B

#### d-5 (숨김): 단톡방 매도와 명예훼손
- A의 단톡방 공개 글이 의도적 매도인지, 판단 섞인 성급한 결론인지
- A: S0-S2 "사실만 썼다", S3+ "판단 섞였다" 인정
- B: S0-S2 "반박 못 했다", S3+ "다은 아버지 꺼내면 가족 무너져서 침묵" 자백
- 주 responder: 양측

### 캐릭터 archetype
- **A (송다은) = premature_summary**: 섣부른 결론짓기. "그게 전부야", "더 볼 것도 없다". 결론 내린 뒤 강화.
- **B (최수민) = affect_flattening**: 감정 억제. 담담한 회피. 핵심 접근 시 말수 급감.

## 4. 쟁점별 + 파티별 atom 설계 지침

각 lieConfig(party × dispute × state)마다 **3~5개 atom**.

### 다양성 요구 (4관점 중 3개 이상)
1. **act / timeline** — fact_pursuit 대응
2. **motive / self_justification** — motive_search 대응
3. **emotion / shame / fear / relationship** — empathy_approach 대응
4. **evidence / context / quote / identity** — evidence_present 대응

### state별 진화 예시 (B / d-1: 9일간의 연락 의도)

| state | atom 방향 |
|-------|----------|
| S0 | 연락 자체 부인 또는 최소화 |
| S1 | 며칠 몇 번 닿은 사실 인정, 의도는 밝히지 않음 |
| S2 | 사적 호감 아님, 분위기 때문이라 둘러댐 |
| S3 | 걱정되는 것이 있어서 확인 시도였다 간접 서술 |
| S4 | "돈 얘기를 피하지 못하겠다" 핵심 단서 흔들림 |
| S5 | A 아버지가 예비신랑에게 같은 수법 쓰는 걸 보고 경고 시도였다 자백 |

### state별 진화 예시 (A / d-5: 단톡방 매도)

| state | atom 방향 |
|-------|----------|
| S0 | 사실만 올렸다고 주장 |
| S1 | 판단 섞인 문장 일부 인정, 의도 아님 강조 |
| S2 | "여러 사람이 볼 줄 알았지만 멈추게 하는 게 먼저" |
| S3 | "반복 자체가 문제" 밀어붙임 (집착 프레임 유지) |
| S4 | "아버지 얘기까지 나오자 분노 제어 못함" 흔들림 |
| S5 | "연락의 뜻을 확인하지 않고 집착으로 단정했다" 인정 |

### Hidden 쟁점 (d-3, d-4, d-5) 특별 규칙

- **d-3 (아버지 돈 패턴)**: S0/S1/S2 "아버지" 언급 금지 (A의 분노 촉발). S3부터 "걱정되는 패턴" 간접, S4 "돈 요구" 등장, S5 "같은 수법" 완전 공개.
- **d-4 (과거 손절과 사기)**: S0~S2 "과거 사기/피해" 금지. S3 "말 못한 사정" 간접, S4 "투자라며 건넨 말" 기억, S5 "돈 돌려받지 못한 피해자" 자백.
- **d-5 (단톡방 매도)**: A는 S3까지 "집착 프레임" 유지. B는 S4까지 "반박 이유" 모호. S5에서 양쪽 모두 사실 공개.

### Truth Throttle 슬롯 매핑

| State | 횟수/기간 | 인물 | 금액 |
|-------|----------|------|------|
| S0-S1 | "며칠" / "몇 번" | neutral | neutral |
| S2 | 대략 범위 | 약칭 | rounded |
| S3+ | exact (9일, 9회) | "송다은 아버지" 등 실명 | exact |
| S4 | 실수 노출 허용 | ... | ... |
| S5 | 전부 | 전부 | 전부 |

## 5. id 명명 규칙

- 형식: `{disputeIdShort}.{meaningKey}`
  - d-1 → d1, d-2 → d2, ... d-5 → d5
  - meaningKey: snake_case
- 같은 atom이 S0~S5 재등장 OK. slot 값만 state별 승격.
- party 간 같은 id 금지.

예:
- `d1.contact_minimize` — B의 d-1 S0 "연락 최소화 주장"
- `d1.warn_intent` — B의 d-1 S5 "경고 의도 자백"
- `d3.father_pattern` — B의 d-3 S5 "A 아버지 수법 완전 공개"
- `d5.stuck_in_certainty` — A의 d-5 S3 "집착 프레임 강화"

## 6. 한국어 품질 규칙 (절대 준수 — 공용 `quality-rules.md`)

### factText
- 의미 라벨 10~30자. 완성 대사 금지.

### slots 내 value
- **이름**: A/B 리터럴 금지. **송다은 / 최수민** 실명.
- **호칭**: `judgeRef`는 "제 친구" / "다은이" (친구 사이 호칭). `directRef`는 "다은", "수민". `angryRef`는 "송다은 씨!" / "최수민 씨!".
- **3인칭 서술**: "송다은 아버지" (B가 언급 시), "제 예비신랑" (A가 언급 시).
- **"송다은 아버지 / 아버지 / 투자 / 사기 / 피해"**: S4+에서만 등장 허용.

### privateKnowledge / suppressions
- B의 privateKnowledge 핵심: "A 아버지에게 과거 사기 당함", "예비신랑에게 같은 수법 쓰는 정황 포착", "A에게 직접 말 못함 (손절/공통 친구)", "자기가 악역이 되는 걸 알면서도 행동"
- A의 privateKnowledge 핵심: "B 손절 후 외로움", "예비신랑 결혼 직전 불안감", "아버지에 대한 복잡한 감정 (남들에게 안 보임)"
- B의 suppressions: 과거 사기 피해 사실, 금액, 아버지 이름 (S4까지 회피)
- A의 suppressions: 아버지 관련 돈 문제 인지 단서 (S4까지 회피)

### tellPool (friend-01 archetype)
- **A (premature_summary)**: `conclusion_lock`, `pattern_claim`, `repetition_emphasis`, `dismissive_wave`, `wrap_up`, `stage_rest`
- **B (affect_flattening)**: `flat_deflection`, `minimal_nod`, `hollow_gaze`, `delayed_response`, `withdrawal`, `self_effacement`

첨부 `friend-01-structure-v2.json`의 `verbalTells` 정의 우선.
