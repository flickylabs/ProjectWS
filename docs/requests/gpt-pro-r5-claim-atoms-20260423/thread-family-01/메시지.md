# GPT Pro 요청 — family-01 v2-atoms 신규 생성

## 이 스레드의 역할

**family-01** 사건의 `v2-atoms` 파일(`claimPolicies` 구조)을 신규 생성합니다.
(다른 사건 spouse-01 / friend-01은 별도 스레드 병렬 진행 중이니 이 스레드에서는 family-01만 다뤄주세요.)

현재 활성 3건에는 v2-atoms가 없어 legacy atom 합성으로 대응 중이고, NPC 응답 다양성 부족이 발생. 이 스레드에서 **family-01 고유 claimAtoms 완전 신규 제작**.

---

## 1. 배경 — Solomon Court와 v2-atoms

Solomon Court는 재판 시뮬레이션 추리 게임. NPC는 거짓말 상태 기계(LieState S0→S5)를 따름:

- S0: 완전 부정 → S1: 일부 인정 → S2: 핑계 → S3: 책임 전가 → S4: 감정적 → S5: 자백

각 state에서 NPC가 답변할 때 사용하는 **발화 재료**가 `claimAtoms`. 완성 대사가 아니라 **의미 원자**.

런타임 흐름:
1. 플레이어 질문(subAction: fact_pursuit / motive_search / empathy_approach / evidence_present) 접수
2. `atomSelectionEngine`이 현 state의 claimAtoms 중 subAction 규칙에 맞는 것 선택
3. `blueprintPromptBuilderV2`가 `factText + slots` 조합해 LLM 프롬프트 구성

당신이 만들 claimAtoms는 이 조합의 **재료 풀**.

## 3. family-01 스토리 배경 (필수 숙지)

### 중심 사건 — 치매 어머니의 유서
- A = **윤태성** (48, 주방가구 공장 대표)
- B = **윤정후** (44, 자동차부품 가게)

### 숨은 진실 (플레이어가 직접 밝혀내야 함)
1. 원래 유서는 **90:10** (B=90%, A=10%). 어머니가 B에게 많이 준 이유: B가 **20년간 매달 생활비**를 어머니에게 보내고, A 사업 실패 때 B 돈으로 빚 갚아줌 (어머니가 "내 돈"이라며 전달).
2. B는 어머니 사망 직전 유서를 **60:40**(B=60, A=40)으로 **자기 몫을 줄여서** 수정.
3. 이유: A와 B는 사실 **이복 형제** (A는 배다른 자식, 어머니 혼자 낳은 사실). B는 **일기장**으로 이 사실을 앎.
4. A는 아버지 회사 대표 → 출생 비밀이 법정에서 터지면 경영권 위기.
5. B는 "법정 가면 일기장까지 터진다. 60:40이면 형이 법정까지 안 간다" 판단으로 수정. **형을 지키기 위한 조작**.

### 5대 쟁점 (첨부 `family-01-structure-v2.json` 참조)

#### d-1 (공개): 유서 작성과 판단 능력
- 진실: 어머니는 말년에 판단 능력 약화되어 있었지만 유서 작성 시점엔 판단 가능
- A: "치매로 판단 못 했다"
- B: "유서 당시엔 뚜렷했다"
- 주 responder: 양측

#### d-2 (공개): 60:40 유서의 진짜 의도
- 진실: B가 자기 몫을 **줄이는** 방향으로 조작 (형 보호 목적)
- A는 초반 "B가 자기 많이 받으려 조작"으로 오해
- B는 진짜 의도 숨김 (출생 비밀 노출 회피)
- 주 responder: 양측

#### d-3 (숨김): 20년 송금의 실체
- 진실: B가 매달 어머니 생활비 + 공장 자금 송금 → 어머니가 **자기 돈**으로 전달
- 주 responder: B

#### d-4 (숨김): 출생 비밀과 침묵의 이유
- 진실: A는 배다른 자식. 어머니 혼자 낳음. B는 일기장으로 앎.
- 주 responder: B

#### d-5 (숨김): 어머니 이용의 진짜 주체
- 진실: B가 유서를 **자기 몫 축소** 방향으로 수정한 진짜 이유 → 형 법정 회피 + 출생 비밀 보호
- A는 "B가 이득 보려 어머니 이용"으로 오해
- 주 responder: B 중심, A는 반응

### 캐릭터 archetype
- **A (윤태성) = confrontational**: 공격적 직설, 분노 표출, 단호. 격앙 시 목소리 커짐.
- **B (윤정후) = affect_flattening**: 감정 억누른 담담함. 표정 변화 적음. 무너질 때도 조용히.

## 4. 쟁점별 + 파티별 atom 설계 지침

각 lieConfig(party × dispute × state)마다 **3~5개 atom**.

### 다양성 요구 (4관점 중 3개 이상)
1. **act / timeline** — fact_pursuit 대응
2. **motive / self_justification** — motive_search 대응
3. **emotion / shame / fear / relationship** — empathy_approach 대응
4. **evidence / context / quote / identity** — evidence_present 대응

### state별 진화 예시 (B / d-2: 60:40 유서의 진짜 의도)

| state | atom 방향 |
|-------|----------|
| S0 | 유서 손댄 적 없음, 어머니 뜻대로라고 주장 |
| S1 | 유서 "준비"에는 관여했으나 내용은 어머니 뜻이라고 물러남 |
| S2 | 어머니 뜻을 옮겼을 뿐 자신 의도 없다 선 긋기 |
| S3 | 90:10을 60:40으로 바꾼 사실 일부 인정, 맥락 해명 시도 |
| S4 | "형 불신만 키운 것 같다" 흔들림, 출생 문제 언저리 |
| S5 | "더 받으려 한 게 아니라 형이 버틸 숫자로 고쳤다" 전면 자백 |

### state별 진화 예시 (A / d-1: 유서 작성과 판단 능력)

| state | atom 방향 |
|-------|----------|
| S0 | 어머니는 말년에 늘 흐렸다며 유서 무효 주장 |
| S1 | 요양 기록 제시 후 "늘"은 아니라고 일부 물러남 |
| S2 | "유서 뜻까지 알았을지 의문"으로 축소 |
| S3 | 판단 흐린 어머니 곁에서 B가 말 골라 넣었을 거라며 책임 전가 |
| S4 | "그날의 어머니를 두고 다투는 일 자체가 돌봄의 시간 모욕" 분노 폭발 |
| S5 | "끝까지 본 사람이라는 자부심 때문에 다른 가능성 밀어냈다" 인정 |

### Hidden 쟁점 (d-3, d-4, d-5) 특별 규칙

- **d-4 (출생 비밀)**: S0/S1/S2에서 출생/일기장/혈연 관련 **절대 금지**. S3+에서도 매우 조심. S4부터 "출생의 틈" 류 간접 표현. S5에서 구체 자백.
- **d-3 (20년 송금)**: S0~S1 금액/횟수 구체 금지. S3부터 점진.
- **d-5 (어머니 이용 주체)**: S0~S2 "자기 몫 축소" 방향성 숨김. S3부터 "내 쪽이 적게 돌아온다" 드러남. S4에서 이유 기울임. S5 완전 공개.

### Truth Throttle 슬롯 매핑

| State | amount/percentage | time | person |
|-------|-------------------|------|--------|
| S0-S1 | neutral ("그 비율", "그 숫자") | neutral | "어머니", neutral |
| S2 | rounded ("60대 40") 가능 단서 한정 | period | 약칭 |
| S3+ | exact (60:40, 90:10) | dateExact | 실명 |
| S4 | 실수 노출 허용 | ... | ... |
| S5 | 전부 | 전부 | 전부 |

## 5. id 명명 규칙

- 형식: `{disputeIdShort}.{meaningKey}`
  - d-1 → d1, d-2 → d2, ... d-5 → d5
  - meaningKey: snake_case 의미 축약
- 같은 atom이 S0~S5 재등장 OK. slot 값만 state별 승격.
- party 간 같은 id 금지 (관점이 다름).

예:
- `d1.mom_confused_always` — A의 d-1 S0 "어머니는 늘 흐렸다"
- `d1.lucid_at_will` — B의 d-1 S1 "유서 작성 시점엔 뚜렷"
- `d2.ratio_shift_admit` — B의 d-2 S3 "90:10→60:40 일부 인정"
- `d4.hidden_diary` — B의 d-4 S4 "일기장에서 알게 된 틈"

## 6. 한국어 품질 규칙 (절대 준수 — 공용 `quality-rules.md`)

### factText
- 의미 라벨 10~30자 축약. 완성 대사 금지.
- 번역체 9패턴 금지.

### slots 내 value
- **이름**: A/B 리터럴 금지. **윤태성 / 윤정후** 실명.
- **호칭**: `judgeRef`는 "제 형"/"제 동생" (재판관에게). `directRef`는 "형"/"동생" (직접). `angryRef`는 격앙 시 "윤정후 씨!"/"윤태성 씨!".
- **비율**: S0-S2 neutral "그 비율". S3+ exact "90대 10", "60대 40".
- **일기장 / 출생 비밀**: S4+에서만 등장 허용.

### privateKnowledge / suppressions
- B의 privateKnowledge 핵심: "형은 배다른 자식", "일기장으로 안 사실", "법정 가면 터짐", "자기 몫 줄여 60:40 수정"
- A의 privateKnowledge 핵심: "자기가 아버지 회사 대표", "출생 비밀 터지면 경영권 위기는 아직 모름", "B가 자기 이익 위해 조작했다고 오해"
- suppressions: 출생/일기장 관련 (B는 S5까지 절대 공개 회피), 20년 송금 세부 (어머니 돈이라 믿음)

### tellPool (family-01 archetype)
- **A (confrontational)**: `rank_pull`, `direct_accusation`, `anger_flash`, `cut_off`, `certainty_claim`, `role_remind`
- **B (affect_flattening)**: `flat_deflection`, `minimal_nod`, `delayed_response`, `no_expression`, `quiet_correction`, `withdrawal`

첨부 `family-01-structure-v2.json`의 `verbalTells` 정의 우선.

## 8. 출력 형식 (엄수)

### 우선 방법 — Code Interpreter / Python

JSON 파일 생성 후 **다운로드 링크**:

```python
import json

data = {
    "caseId": "family-01",
    "schemaVersion": "v2",
    "claimPolicies": {
        "a": {
            "d-1": {
                "S0": {
                    "disputeId": "d-1",
                    "state": "S0",
                    "schemaVersion": "v2",
                    "claimAtoms": [
                        {
                            "id": "d1.mom_confused_always",
                            "factText": "어머니 말년 판단능력 전반적 상실 주장",
                            "tags": ["identity", "context", "denial"],
                            "slots": {
                                "person": {"fullName": "어머니", "judgeRef": "저희 어머니", "neutral": "어머니"},
                                "time": {"period": "말년", "neutral": "그 무렵"}
                            },
                            "stanceHints": ["deny"],
                            "source": "v2"
                        },
                        # ... 추가 atom
                    ],
                    "privateKnowledge": [
                        "어머니가 유서 작성 시점엔 판단 가능했던 정황 인지",
                        "하지만 유서 내용 자체에 대한 불만이 주 원인"
                    ],
                    "suppressions": [
                        "자기 사업 실패로 B 돈을 받았던 과거"
                    ],
                    "emotionalLeakRisk": "low",
                    "tellPool": ["rank_pull", "certainty_claim", "direct_accusation"]
                },
                # ... S1-S5
            },
            # ... d-2 ~ d-5
        },
        "b": { ... }

with open('/mnt/data/family-01-v2-atoms.json', 'w', encoding='utf-8') as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

print(f"File size: {len(json.dumps(data))/1024:.1f} KB")
print(f"Total atoms: {sum(len(v2['claimAtoms']) for party in data['claimPolicies'].values() for dispute in party.values() for v2 in dispute.values())}")
```
