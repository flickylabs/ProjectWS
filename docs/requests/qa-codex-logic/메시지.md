# Codex QA — 로직/기능성 심층 검증 (20라운드)

## 프로젝트 개요

**솔로몬 법정**: AI 당사자 둘의 분쟁을 인간 플레이어가 재판관으로 판결하는 리플레이형 추리 게임.
React 19 + TypeScript 5.9 + Vite 8 + Zustand 5 기반. PC 전용.

### 게임 흐름
```
Phase 0: 사건 브리핑 → Phase 1: 사전진술(선택지) → Phase 2: 심문(본게임)
→ Phase 3a: 중재 → Phase 3b: 판결 → Result: 결과/보너스
```

코드상 enum은 다르지만 Phase alias가 있음:
```
Phase.Briefing = GamePhase.Phase0_CaseIntro = 'phase0'
Phase.Pretrial = GamePhase.Phase1_InitialStatement = 'phase1'
Phase.Interrogation = GamePhase.Phase3_Interrogation = 'phase3'
Phase.Mediation = GamePhase.Phase6_Mediation = 'phase6'
Phase.Verdict = GamePhase.Phase7_Verdict = 'phase7'
Phase.Result = GamePhase.Result = 'result'
```
Phase2_Rebuttal, Phase4_Evidence, Phase5_ReExamination은 deprecated (PHASE_ORDER에서 제거됨).

### 핵심 시스템
- **토큰**: investigationTokens=20, skillPoints=10, courtControl=5 (로컬 resourceSlice 단일 관리)
- **LieState**: S0(완전부정)→S1(일부인정)→S2(핑계)→S3(전가)→S4(감정적)→S5(자백)
- **심문 3종**: fact_pursuit(모순추궁), motive_search(동기탐색), empathy_approach(공감접근)
- **최대 턴**: 16 (초과 시 강제 판결)
- **증거**: 7개, 해금 체인 있음 (requires 필드)
- **모순 감지**: contradictionTokens ≥ 3, 쿨다운 4턴, 같은 쟁점 6턴
- **공감 자백**: S3+ & trust ≥ 70 & empathyAtCurrentState ≥ 2
- **재판관 성향**: 9종 조각(3축×3방향), 6성향 강화, 15퍼크
- **중재 유형**: immediate/conditional/postpone/fact_first → Phase 7 점수 보정

## 검증 라운드 (20회)

각 라운드에서 해당 코드를 **직접 읽고 로직을 추적**하여 검증합니다.

### Phase 흐름 (R1-R3)
**R1.** PHASE_ORDER 정합성
- `constants.ts`의 PHASE_ORDER에 Phase2_Rebuttal이 없는지
- Phase.Briefing → Phase.Pretrial → Phase.Interrogation → Phase.Mediation → Phase.Verdict → Phase.Result 순서

**R2.** advancePhase 동작
- skipTo가 있으면 해당 phase로, 없으면 PHASE_ORDER 순차
- Phase.Interrogation 진입 시 applyPhase3Bridge 호출 (phaseSlice.ts)
- 강제 판결: 16턴 초과 시 Phase.Mediation으로 전환 (incrementTurn 내)

**R3.** Phase alias vs enum 값 일치
- 모든 switch/case와 비교식에서 Phase.X와 GamePhase.PhaseN_XXX가 같은 값인지
- 특히 PCApp.tsx, PCCourtLayout.tsx, PCBottomDock.tsx의 분기

### 토큰 경제 (R4-R7)
**R4.** 초기값 + initResources
- INITIAL_RESOURCES = { investigationTokens: 20, skillPoints: 10, courtControl: 5 }
- initResources()가 이 값으로 리셋하는지

**R5.** spend 정합성
- 모든 리소스 유형이 로컬 resources 객체에서 차감되는지
- 글로벌(globalInvestTokens 등)으로 리디렉트하지 않는지 (이전 버그 수정 확인)
- canAfford도 로컬 resources를 체크하는지

**R6.** canUseSkill 정합성
- SKILL_COSTS 참조 → canAfford() 호출 → 로컬 resources 체크
- 이전 버그: resources[cost.resource]가 항상 초기값(10)이었음 → 수정 확인

**R7.** 토큰 차감/환불 코드 경로
- handleEvidenceInvestigate: spend('investigationTokens', 1) 존재 확인
- 증인 소환 실패 시: gain('investigationTokens', 1) 환불 확인
- 미니게임 성공 시: gain(resourceKey, 1) 확인

### 심문 엔진 (R8-R11)
**R8.** fact_pursuit 효과
- contradictionTokens 증가 로직
- 교착 감지: streak ≥ 3 → 'stalemate', streak 2 → 'warning'
- 교착 메시지에 구체적 대안(다른 심문 유형명) 포함 확인

**R9.** motive_search 효과
- leakMeter 증가 로직
- hidden_dispute_hook: S2+ & leak 40%+ 시 발생
- 대화 로그에 "동기 탐색이 효과를 보이고 있습니다" 메시지

**R10.** empathy_approach 효과 + 밸런스 조정
- trust 증가: +12 기본 + emotion 보너스
- empathyAtCurrentState 카운터: empathy_approach 사용 시 +1
- 자백 조건: trust ≥ 70 AND empathyAtCurrentState ≥ 2 (S3+ 상태)
- lieState 전이 시 empathyAtCurrentState 리셋

**R11.** 교착 안내 메시지 품질
- stalemate 시 "사실 추궁 또는 공감 접근으로 전환하거나, B측을 심문하거나, 다른 쟁점을 시도해 보세요" 형태
- questionType에 따라 대안이 올바르게 필터링되는지

### 이벤트 트리거 (R12-R13)
**R12.** 모순 감지 정합성
- 조건: contradictionTokens ≥ 3, lieState S0-S2, 쿨다운 4턴
- 같은 쟁점 연속: lastContradictionDisputeId 비교, 6턴 쿨다운
- **activeParty**: `separationTarget ?? pcTargetParty ?? 'a'` — B 선택 시 B로 판정되는지

**R13.** 감정 폭발/끼어들기
- 감정 폭발: internalValue ≥ 75
- 끼어들기: 최소 3턴 간격

### 증거 시스템 (R14-R15)
**R14.** spouse-01 해금 체인
- e-1,e-2,e-3: requires [] (초기 해금)
- e-4: requires ["e-3"]
- e-5: requires ["e-4"]
- e-7: requires ["e-5"] ← 적금 해지가 먼저
- e-6: requires ["e-7"] ← 카톡이 나중
- e-6이 e-7보다 절대 먼저 해금되지 않는지

**R15.** investigationStages 데이터 존재
- 3사건 모든 증거에 investigationStages 배열이 있는지
- 각 stage 0/1/2, unlockHint 필드 존재

### 판결/결과 (R16-R18)
**R16.** calculateVerdict 보너스 연결
- ProcessMetrics의 combinationDossierUnlocked, counterQuestionUsed, bothSidesS3Plus
- 각 필드가 0이 아닌 실제 값을 가질 수 있는 경로 확인
- verdictEngine에서 해당 보너스(+10, +5, +10)가 정상 반영

**R17.** mediationEffects 점수 보정
- PCVerdictScreen에서 mediationChoice 읽기 → computeMediationScoreModifiers 호출
- evaluateCondition이 단순 비교(==, >=, <=, &&)를 정확히 평가하는지
- per-dimension cap(6), net cap(10) 적용

**R18.** 조각 획득 계산
- computeCaseRewards: |caseAxis| ≥ 45 → 방향 3, 15-44 → 방향 2 + 중립 1, <15 → 중립 2
- 보너스 조건 5종 각각의 판정 로직

### 성향 시스템 (R19-R20)
**R19.** 강화 비용 + canEnhanceTrait
- ENHANCEMENT_COSTS: Lv0→1(방향3+중립5), Lv1→2(방향6+중립10), Lv2→3(방향10+중립16)
- 인벤토리 잔액 체크 정확성

**R20.** 변환 + 퍼크 해금
- convertFragments: 중립 3 → 방향 1, 같은 축 내만
- getAllUnlockedPerks: major는 Lv3, minor는 Lv1 조건
- getEquippedEffects: 장착 퍼크 effect 합산
