## 사용자 인식과 코드 상태의 갭

사용자 메시지: *"Intro, Home, Session 선택창, 사건 선택창, 프로필, 설정창 등은 손대야할게 무척 많을 것 같아. 디자인 전체를 갈아엎어야 할 수 있어."*

**코드 분석 결과**: 위 화면 중 **Intro / Home / 사건 선택**은 이미 PC 디자인 톤(골드 + 다크 우드 + 글래스모픽)으로 정비되어 있음. 사용자가 인지한 "갈아엎기"는 다음 중 하나일 가능성:

1. **인지 시점 갭** — Phase 1~2 정비 후 더 정교해진 기준에 비추면 미흡 (실제로 일부 차이 있음 — 아래 상세)
2. **신규 시그니처 변경** — 새 토큰(spacing/radius/font scale) 적용으로 미세 조정 필요
3. **추가 콘텐츠 요구** — 디자인이 아니라 정보 밀도/레이아웃 자체 재구성

**권고**: 사용자 dev 검증 종료 후 1순위 작업 전에 **"갈아엎기"의 의미를 사용자에게 1회 확인**. 코드상 이미 정비된 화면을 다시 갈아엎으면 회귀 위험 + 시간 낭비.

## 화면별 상세 진단

### 1. 🟢 Intro 슬라이드 (`PCIntroSlides.tsx`)
- **상태**: PC 톤 적용, 슬라이드 패턴 정립
- **검토 항목**: 슬라이드 전환 애니메이션 토큰 적용 여부, 폰트 스케일 일관성
- **추천 변경**: 토큰 도입 시 미세 조정 (XS 작업)
- **회귀 위험**: 낮음

### 2. 🟢 Home 메인 메뉴 (`PCHomeScreen.tsx`, 31KB)
- **상태**: 메인 카드 + 사이드 정보 카드, 골드 톤 정립
- **하위 컴포넌트**: PCCaseBrowser, PCCaseProgression, PCJudgeProgressionPanel
- **CSS**: `pc.css`에 `pc-home-v2-*`, `pc-mode-card-*` 클래스 다수
- **검토 항목**:
  - 신규 모드/메뉴 추가 시 카드 패턴 통일성
  - 정보 카드 그라디언트 패턴 일관성
- **추천 변경**: 새 토큰 적용 + 카드 그리드 시스템 정리 (M 작업)
- **회귀 위험**: 중간 (큰 컴포넌트, 변경 시 영향 범위 큼)

### 3. 🟢 사건 선택 (`PCCaseBrowser.tsx`)
- **상태**: 사건 카드 그리드, 카테고리 필터
- **CSS**: `pc-case-browser-*`, `pc-session-card-v2-*`
- **검토 항목**:
  - 사건 카드 호버/선택 효과 (골드 펄스 적용?)
  - 카테고리 탭/필터 디자인 (Chip 패턴?)
  - 빈 상태 / 잠금 상태 표현
- **추천 변경**: 카드 호버 + 잠금 표시 통일 (M 작업)
- **회귀 위험**: 낮음

### 4. 🟢 사건 브리핑 / Phase 0 (`PCCaseBrief.tsx`)
- **상태**: 사건 소개 + 시작/취소 버튼

### 5. 🟢 Phase 1~2 게임플레이 — **기준점**
- 디자인 시스템의 표준
- 변경 X (다른 화면이 여기 맞춤)

### 6. 🔴 Phase 3a 중재 (`Phase6_Mediation.tsx`) — **1순위**
- **현 상태**:
  ```
  - 4개 옵션 버튼(즉시/조건/보류/사실 먼저)을 단순 리스트로 표시
  - .pc-mediation__* 클래스 사용하지만 pc.css에 정의 거의 없음
  - 골드 톤, 글래스모픽 미적용
  - 로딩 표시는 단순 spinner
  - "판결로 진행" 버튼 디자인 미흡
  ```
- **문제**:
  - 심문(Phase 1~2) → 중재 → 판결로 넘어가는 흐름에서 **시각적 단절감**
  - 4개 선택지가 "결정의 무게"를 표현하지 못함
- **권장 작업**:
  1. 4개 옵션을 큰 카드로 재구성 (각각 아이콘 + 라벨 + 설명 + 호버 시 골드 펄스)
  2. 헤더에 "재판관의 결정" 같은 제목 강조 (H1 사이즈)
  3. 선택 후 양측 반응 대화는 게임플레이 톤 유지 (말풍선 그대로)
  4. "판결로 진행" 버튼을 Primary(Gold) lg 사이즈로
- **작업량**: L (반일~1일)
- **선결 조건**: 디자인 토큰 도입 (가이드 적용) 후

### 7. 🟢 Phase 3b 판결 (`PCVerdictScreen.tsx`, 80KB)
- **현 상태**: 4단계 판결 순서도 UI (FactChecklist → ResponsibilitySlider → SolutionPicker → EvidenceLegality)
- **CSS**: `pc-verdict-*` 다수
- **사용자 메시지**: "레이아웃 및 비율은 거의 잡아놓은 셈이니 컬러, 버튼 디자인 등만 변경"
- **권장 작업**:
  - 단계 indicator 골드 톤 적용
  - 슬라이더/체크리스트 컴포넌트 토큰 치환
  - 버튼 4종 변형으로 정리 (S 작업)
- **회귀 위험**: 중간 (대형 컴포넌트, 충분한 dev 검증 필요)

### 8. 🟢 결과 (`PCResultScreen.tsx`, 200KB)
- **현 상태**: 4탭 시스템(결과/선고/후일담/보너스) + 프래그먼트 보상 오버레이
- **CSS**: `pc-result-*`
- **권장 작업**:
  - 탭 구조 골드 라인 강조
  - Hero 점수 폰트 토큰 적용
  - 후일담 텍스트 가독성 (line-height + 여백) (S 작업)

### 9. 🟠 설정 (`PCSettingsPanel.tsx`) — **2순위**
- **현 상태**:
  ```
  - 모달 형태 (createPortal)
  - 해상도 설정 단일 섹션만 존재
  - 오디오/사운드/알림 등 핵심 옵션 없음
  - 골드 톤 부분 적용, 카드 그리드 미흡
  ```
- **권장 작업**:
  1. 설정 카테고리 사이드바 + 우측 컨텐츠 (좌/우 분할)
  2. 카테고리 신설:
     - 화면 (해상도, 풀스크린)
     - 오디오 (마스터/BGM/SFX)
     - 게임플레이 (텍스트 속도, 자동 진행)
     - 데이터 (저장 슬롯, 백업)
     - 정보 (버전, 크레딧)
  3. 옵션 컴포넌트 표준화 (토글, 슬라이더, 셀렉트, 라디오)
  4. 모달 → 풀스크린 화면으로 변경 검토 (체류 시간 길어짐 예상)
- **작업량**: M (반일~1일, 기능 신설은 별도)
- **회귀 위험**: 낮음 (현재 거의 빈 화면)

### 10. 🟠 프로필 / Judge Desk — **2순위**
- **현 상태**:
  ```
  - PC: PCHomeScreen 내부 view='profile' 진입 → PCJudgeProgressionPanel 등 표시
  - 모바일 유산: ProfilePage.tsx (modal 스타일)

  ```
- **권장 작업**:
  1. Judge Desk 풀스크린 레이아웃 (3섹션):
     - 좌: 재판관 프로필 (이름/칭호/성장 단계)
     - 중: 9조각 인벤토리 (3축 × 3방향 그리드)
     - 우: 6성향 레벨 + 15퍼크 (Major 6 + Minor 9)
  2. 조각 카드 디자인 (희소성/방향별 컬러)
  3. 퍼크 장착 UI (Major 1 + Minor 1 슬롯)
  4. 통계/사건 기록 탭 추가
- **작업량**: L (1~3일, 기획 정리 포함)
- **선결 조건**: 사용자에게 정보 우선순위 확인

### 11. ⚪ 세션 선택 (`SessionSelect.tsx`) — **보류**

## 권장 작업 순서

### Phase A — 토큰 정립 (선결)
1. `PC-UI-DESIGN-SYSTEM.md` 가이드 검토 + 사용자 승인
2. `src/app/pc.css :root`에 신규 토큰(spacing/radius/font/transition) 추가
3. `--pc-amber` → `--pc-gold` 통합 (단순 alias 정리)
4. 회귀 위험: 0 (토큰 추가만, 사용 X)

### Phase B — 1순위 (Phase 3a 중재) 리뉴얼
1. 4개 옵션 카드 디자인 재설계 (mock 1~2 패턴 제안)
2. 사용자 검토 후 적용
3. 작업량: L

### Phase C — 2순위 (설정 + 프로필)
1. 설정: 카테고리 신설 + 옵션 컴포넌트 표준화
2. 프로필: Judge Desk 풀스크린 레이아웃
3. 작업량: M + L

### Phase D — 정비됨 화면 미세 조정
1. Home/Intro/사건 선택/브리핑: 토큰 점진 치환 + "갈아엎기"의 정확한 의미 사용자 확인 후 결정
2. 판결/결과: 컬러/버튼만 토큰 치환 (사용자 명시)
3. 작업량: 화면별 XS~M

## 사용자 확인 필요 사항

다음 사항을 사용자 dev 검증 종료 후 확인:

1. **"갈아엎기"의 의미** — Intro/Home/사건 선택은 이미 PC 톤 적용된 상태. 추가 변경의 방향?
   - (a) 미세 조정만 (토큰 치환)
   - (b) 정보 밀도/레이아웃 재구성
   - (c) 시각 스타일 자체 변경 (예: 다른 컬러 베이스)

2. **설정 화면 신설 옵션** — 어떤 카테고리/옵션 추가할지
   - 오디오 컨트롤 (마스터/BGM/SFX) 신설?
   - 텍스트 속도/자동 진행 등 게임플레이 옵션?

3. **Judge Desk 정보 우선순위** — 어떤 데이터를 메인으로 보여줄지
   - 9조각 인벤토리 우선?
   - 6성향 레벨 차트 우선?
   - 사건 기록 우선?

4. **모달 vs 풀스크린** — 설정/프로필을 모달 유지 vs 풀스크린 화면으로 변경?

5. **Phase 3a 중재 톤** — "결정의 무게"를 어떻게 표현할지
   - 카드 4장 그리드 (현재 안)
   - 시퀀셜 단계 진행 (좀 더 정제된 느낌)
   - 말풍선처럼 재판관 톤으로 안내 후 선택

## 작업 시간 추정 (참고)

가이드 적용 + 모든 화면 리뉴얼 시:

| 항목 | 시간 |
|---|---|
| 토큰 정립 (Phase A) | 0.5일 |
| 1순위 (Phase 3a 중재) | 1일 |
| 2순위 (설정 + 프로필) | 2일 |
| 3순위 (Home/Intro/사건 선택 미세 조정 OR 갈아엎기) | 1~3일 (사용자 답변 따라) |
| 판결/결과 컬러·버튼 치환 | 0.5일 |
| **합계** | **5~7일** |

각 단계마다 사용자 검토 + dev 검증 1회씩 권장.
