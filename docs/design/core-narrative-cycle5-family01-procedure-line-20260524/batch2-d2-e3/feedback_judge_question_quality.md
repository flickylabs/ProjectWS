## 재판관 질문 품질 규칙

### 절대 금지 패턴

1. **기계적 관찰문**
   - "태도에 변화가 감지됩니다" / "내용이 확인됩니다" / "흐름이 나타납니다"
   - 이런 표현은 시스템 로그 톤이지 재판관 말투가 아님

2. **긴 발언 직접 인용**
   - `'각방 중이었으니 더 잘 들렸습니다. 문틈 너머로...'라고 하셨는데`
   - NPC 발언을 그대로 따옴표에 넣으면 부자연스러움
   - **간접 인용으로 요약**: "아까는 ~쪽으로 말씀하셨는데" / "처음에는 ~취지였는데"

3. **시스템 관찰 + 직접 인용 결합**
   - `'${prev}'라고 하셨는데, 현재는 '${curr}'라는 내용이 확인됩니다`
   - 따옴표 안에 시스템 문구가 들어가면 최악

### 올바른 패턴

- **간접 화법**: "아까는 ~쪽으로 말씀하셨는데, 지금은 ~. 왜 달라졌습니까?"
- **재판관 관찰**: "말씀이 조금씩 달라지고 있습니다" / "처음과 다른 이야기를 하고 계십니다"
- **직접적 질문**: "어느 쪽이 사실입니까?" / "왜 바뀐 겁니까?"

### 톤 단계별 기준
| 단계 | 톤 | 예시 |
|------|-----|------|
| soft (S0-S1) | 정리 요청 | "어느 쪽이 맞는 건지 정리해 주시겠습니까?" |
| mid (S2) | 추궁 | "왜 말이 달라졌습니까?" / "분명히 해 주십시오" |
| hard (S3+) | 단호 | "어느 쪽이 진실입니까?" / "경위를 밝히십시오" |

### 시스템 메시지도 동일 기준
- "진술 태도에 변화가 감지된다" → "진술이 달라지기 시작한다"
- 기획 용어, 분석 톤 금지 → 관찰자가 보고하는 서술체

**Why:** 플레이어가 재판관으로 몰입하는 게임인데, 재판관 대사가 기계적이면 몰입이 깨짐.
**How to apply:** 새 사건 ScriptedText 생성, judgeQuestionEngine 수정, QA 검증 시 이 기준으로 체크. threadC 품질 검증에도 해당 패턴 감지 추가 검토.
