## #1 데이터 직접 read 검증
- 산출물 작성 전 source 파일을 직접 read 검증
- 사건 인물/사실/비율을 추측 X, source에 명시된 대로

## #2 임의 이름/정보 작성 X
- source 파일에 명시되지 않은 인물 이름/장소/금액 사용 X
- "박씨", "김씨" 등 일반적 이름 X (정확한 캐릭터 이름 사용)

## #3 다른 사건 정보 혼입 X
- spouse 작업 중 family/friend 인물/사실 혼입 X
- 각 사건은 자기완결 처리

## #4 신규 작성 vs 보완 혼동 X
- "보정" 작업은 기존 본문 의미 보존하면서 표현 보정
- 사용자 detail 메시지는 항상 보완 방향
- 신규 작성으로 회피하지 마

## #5 사용자 detail 메시지 = 항상 보완 방향
- 사용자가 detail 피드백 주면 = 그 부분 깊이 보완
- 다른 영역으로 우회 X

## #6 보정 = 9차원 맥락-의미 정확성 (★ 가장 중요)
- 단순 어휘 교체 X (글자수 / 단순 단어 변경)
- 9차원 (캐릭터 archetype × lieState × emotion × contradict_token × tone × 시점 × 인지 단계 × 추궁 차원 × NPC voice) 정확 매핑

- **friend-01 사례**: dossier id 형식 잘못 (`a-dc1-q1-...` vs 통합 `dc-1-a-q1-...`). 폐기.
- 한 산출물에서도 일부 정합 / 일부 충돌 가능 (family-01 S8: aftermath OK / tonePatch 충돌)
