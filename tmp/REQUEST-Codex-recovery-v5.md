# Codex 종합 수습 의뢰 v5 — 광범위 동형 사례 검출 강화 (틀 잡기)

> **작업 성격**: v4 (P1~P6 의미·맥락 보정) 회수 후 ClaudeCode CT 검증 결과, 사용자 11 사례 92% 처리(12/13)는 OK이나 **동형 사례 광범위 검출에 실패**. v5 = 사용자 사례를 "예시"로 보고 14,931 variants 전수에서 동형 광범위 처리.
>
> **사용자 명시**: "한 글자 한 글자가 중요한 게 아니라, 수정이 필요한 이유를 이해해서 전체 수정 가이드를 제대로 세우는 게 중요" + "일단 틀을 잡는 게 중요해".
>
> **시간 제약 없음**. v4 잔여 + 광범위 동형 검출 강화. 사용자 사례는 *시작*이지 *완료*가 아님.

### 2.2 잘못 패턴 #11 (NEW v5)

**규칙**: 사용자가 spot check로 보여준 사례는 *시작점*이지 *완료 list*가 아니다. 같은 패턴을 가진 동형 사례를 14,931 variants 전수에서 광범위 검출 + 처리해야 한다.

**Why**: v4에서 사용자 11 사례 92% 처리(12/13)는 OK이나, 그 외 동형 사례 광범위 검출에 실패. P2 동형 36건, P1 광범위, P3 광범위 잔여. 사용자 명시 "한 글자가 중요한 게 아니라 수정이 필요한 이유를 이해해서 전체 수정 가이드 세우는 게 중요".

**How to apply**:
1. 사용자 사례에서 패턴(이유) 추출
2. 그 패턴의 검출 알고리즘(정규식/키워드) 정의
3. 14,931 variants 전수 검출
4. 모든 검출 entries 처리 (사용자 명시 사례만 처리 X)
5. 종료 조건에 "동형 매트릭스 PASS" 포함

## 3. 광범위 검출 강화 (★ v5 핵심)

### 3.1 P2 캐릭터 화법 — 시적/추상 검출 키워드 list

다음 키워드 / 패턴이 NPC 발화에 있으면 **모두** patch 후보:

#### 3.1.1 비유/은유 동사
- `냄새가 났`, `냄새가 풍`, `향기가`
- `마음이 무너`, `마음이 끌`, `마음이 흔들`, `마음이 떨`, `마음이 가라앉`
- `가슴이 무너`, `가슴이 미어`, `가슴이 답답`
- `장면이 자꾸 남`, `장면이 떠올`, `머릿속에 남`
- `두려움이 제 선택`, `두려움이 저를`, `불안이 저를`, `의심이 저를`
- `한 발 옮긴`, `한 걸음 물러`, `한 박자 늦`
- `방향으로 흘렀`, `같은 방향으로 겹`, `같은 방향을 가리`

#### 3.1.2 추상 명사 주어
- `기록과 물건이`, `기록이 그`, `자료들이 그`
- `그 종이 한 장`, `그 두려움`, `그 단서`
- `그 장면`, `그 흐름`, `그 패턴`

#### 3.1.3 시적 결구
- `종이 한 장도 그냥 못 넘`
- `그 장면이 자꾸 남`
- `더 무서웠습니다` (단독 — 영수증 등 구체 명시 없을 때)

#### 3.1.4 처리 방향
- 시적/은유 → 일상 직설 (archetype voice 보존)
- 비유 동사 → 직설 동사 ("냄새가 났다" → "느낌이 들었다")
- 추상 주어 → 구체 주어 ("그 종이 한 장" → "영수증 / 문자 / 기록")
- 시적 결구 → 직설 결구 (의미 보존, 화법만 일상화)

#### 3.1.5 검출 + patch 합산 목표
- 사용자 사례 5건 + 잔여 동형 36건 + 추가 검출 + 다른 키워드 잔여 = **최소 50건 이상 처리 예상**

### 3.2 P1 Q-A 정합 — 광범위 검출 알고리즘

#### 3.2.1 알고리즘

```
모든 NPC interrogation entry에 대해:
1. variantId에서 disputeId / lieState / questionType 추출
2. 같은 disputeId × lieState × questionType의 재판관 질문 entry 찾기
   - judge_question 채널에서 같은 disputeId + 같은 questionType
   - 또는 ScriptedText의 entry-question 매칭 정의
3. 재판관 질문의 추궁 차원 식별:
   - "지키려 한 것" / "두려워 한 것" / "가장 먼저" / "다른 선택지" / 
     "직접 본 것 vs 짐작" / "어떤 일" / "왜" / "결과 / 과정"
4. NPC 답변의 의미 차원 분석:
   - 답변이 그 차원에 정합?
   - 차원 어긋남 → P1 후보
5. archetype voice 보존하면서 답변 차원 재정렬
```

#### 3.2.2 차원 매핑 가이드

| 재판관 질문 차원 | NPC 답변 정합 차원 |
|---|---|
| "가장 먼저 지키려 했던 것" | 가치 / 가정 / 자존감 / 결혼 / 입지 |
| "가장 두려워한 것" | 결과 / 결말 / 손실 / 이혼 / 평판 |
| "다른 선택지" | 대안 / 가능성 / 다른 해석 |
| "직전에 무슨 일" 또는 "외에 다른 일" | 시간 순 사건 / 정황 |
| "직접 본 것 vs 짐작" | 관찰 vs 추론 분리 |
| "왜 그렇게 확신" | 동기 / 이유 / 근거 |
| "어떤 마음" | 심정 / 정서 |
| "어떤 일" | 행동 / 사건 |

#### 3.2.3 검출 + patch 합산 목표
- 14,931 variants 중 NPC interrogation은 약 4,500+ entries (4 questionType × N disputes × N lieState × N variants)
- 그 중 Q-A 정합 어긋남 entries 광범위 처리 — **최소 100건 이상 예상**

### 3.3 P3 재판관 추궁 각도 — 추상 부사구 검출

#### 3.3.1 추상 부사구 키워드

```
"관련해서", "당시", "그것에 대해", "그에 관해", "이에 대해",
"어떤 일이", "어떻게 X 했는지",
"다른 선택지", "직전에는", "이후에는", "이전에는",
"나중에 들은", "들으셨다면",
"분명히", "정확히", "구체적으로" (재판관 강조어),
```

#### 3.3.2 노골 패턴 (★ 누설 가까운 X)

- "X와 Y을 주고받은 적" (메시지 진실 가리킴)
- "X를 본 적이 있" (증거 진실 가리킴)
- evidence 진실 lexeme 가까운 명시

#### 3.3.3 처리 방향
- 추상 부사구 → 추궁 본질 명료화
- 노골 → 거리감 추가 ("연락 주고받은 적" → "짐작할 수 있는 다른 정보")

#### 3.3.4 합산 목표
- 재판관 4채널 약 600+ entries
- 추상 / 노골 검출 — **최소 30건 이상 예상**

## 13. 마무리 — Codex에게

v4 작업은 사용자 11 사례 92% 처리로 정확한 의미 보정 능력을 보여줬습니다. 단 사용자가 명시 안 한 동형 사례는 광범위 검출에 실패해 P2 시적 표현 36건, P1 광범위, P3 광범위가 잔여로 남았습니다.

v5의 핵심은 "**동형 광범위 검출이 본질**"입니다. 사용자 사례는 패턴 단서이지 처리 list가 아닙니다. 14,931 variants 전수에서 같은 패턴을 가진 동형 사례를 검출 + 처리해야 "전체 수정 가이드를 제대로 세우는" 본질에 부합합니다.

3절 광범위 검출 list가 핵심. 각 specialist가 자기 영역의 키워드/알고리즘을 14,931 variants에 적용해 모든 동형 사례 처리. 종료 조건이 "사용자 사례 fix"가 아니라 "광범위 매트릭스 PASS"임을 항상 인지.

자체 검증 PASS 후 `tmp/codex-recovery-v5/FINAL-REPORT-v5.md`로 종합 보고. 광범위 검출 매트릭스 통계 (검출 N → 처리 N → 잔여 0)를 명시.
